# نقل سدد إلى Flutter

هذا مشروع Flutter جديد داخل `Sadad-Flutter`؛ جميع الواجهات والمنطق والتخزين والمزامنة مكتوبة بلغة Dart. ملف Android `MainActivity.java` جسر تشغيل Flutter فقط، وملفات Swift تشغل Flutter على iOS.

## ما نُقل

| الجزء | التنفيذ في Flutter |
|---|---|
| التصميم | واجهات Material أصلية، عربية RTL، شعار سدد الأصلي، أبيض وأخضر، مظهر داكن، أرقام إنجليزية |
| الأشخاص | البحث بالاسم أو الهاتف، منع التكرار، حد دين اختياري، ملاحظات، أرشفة واستعادة، إبقاء الأرصدة الصفرية آخر القائمة |
| الديون | إنشاء، استحقاق اختياري، ملاحظات، تصحيح مع السبب ورقم النسخة |
| الدفعات | نقدي/بنك/محفظة، اختيار الدين، منع الدفعة المتطابقة للشخص خلال دقيقة، عكس مع الاحتفاظ بالأصل |
| السجل | آخر حركة لكل شخص أو جميع الحركات، يوم/شهر/سنة/فترة مخصصة |
| التقارير | PDF عربي محلي بخط Tajawal، طباعة، مشاركة، إيصال دفعة معتمدة، سند صرف مستقل |
| الحسابات | حتى ثلاثة حسابات، عزل البيانات حسب عنوان API والمتجر، اسم مستخدم الجهاز وصلاحياته |
| القفل | PIN مشتق باستخدام PBKDF2، إبطاء المحاولات المتكررة، بصمة/Face ID، قفل عند الانتقال للخلفية |
| المزامنة | SQLite، طلب ثابت لكل عملية وUUID، إعادة إرسال نفس الطلب، فصل العرض المؤقت عن المعتمد، معالجة التعارض وتغير نسخة الخادم |
| الخلفية | Workmanager على Android؛ إعداد Background Fetch في مشروع iOS، وفق جدولة النظام |
| واتساب | حفظ إعداد Meta على الخادم؛ مشاركة PDF من قائمة المشاركة |
| الإملاء | إملاء الأسماء والملاحظات والمبلغ، ثم مراجعة المستخدم قبل الحفظ |
| التنبيهات | قائمة داخل التطبيق للمستحقات والعمليات التي تحتاج متابعة |

## حالة الربط الرسمي

العنوان الافتراضي:

```
https://vhftjmiltqfwmrszdtgf.supabase.co/functions/v1/sadad-api/api
```

مفتاح التطبيق الموجود في `lib/core/config.dart` هو مفتاح **publishable** عام. لا توجد مفاتيح service-role أو كلمات مرور إدارية في تطبيق Flutter.

العميل يستخدم تسجيل دخول سدد `mobile/login` مع deviceId واسم مستخدم الجهاز، ثم عقد العمليات الموجود في `../Supabase-Setup/IMPLEMENTATION_PLAN.md`:

- `GET mobile/v3/snapshot?after=...&epoch=...`
- `POST mobile/v3/operations`

**ملفات الخادم التي كانت موجودة عند التحويل لا تحتوي مسارات v3 المكتملة ولا دوال SQL الخاصة بها.** توجد هياكل الجداول ومساعدات جزئية. لم يُغيّر هذا التحويل ملفات الخادم أو ينشرها، ولم يُثبت اتصال العمليات مع Supabase حيًا. يحتاج العمل الرسمي استكمال تلك المسارات والدوال ونشرها وترحيل المتجر وفق دليل الخادم.

عند 404 أو `migration_required` يقرأ التطبيق `mobile/snapshot` للعرض، ولا يرفع نسخة الهاتف القديمة إلى الخادم. لا يُقدّم التطبيق الاستجابة الناقصة كنجاح مالي. حسابات السجل القديم تظهر للقراءة حتى اكتمال الترحيل.

ربط Meta الموجود في API يمكن حفظه. إرسال كشف UUID مباشرة من الخادم يحتاج تحديث مسار واتساب القديم؛ مشاركة ملف PDF تعمل من الهاتف. بوابة العميل الرسمية تتطلب SMS OTP وربط الحسابات في الخادم؛ لا يوجد تحقق وهمي في النسخة الرسمية.

## البيانات القديمة والتثبيت

- هوية Android الرسمية الجديدة `com.sadad.app.flutter`، والتجربة `com.sadad.app.flutter.test`؛ يمكن تثبيتهما بجانب التطبيق القديم.
- SQLite الجديد `sadad-flutter-v4.db`. لا يفتح التطبيق `sadad.db` القديم ولا يحذف أي ملفات منه.
- نقل SQLite القديم إلى Supabase يتطلب تحديد مالك كل سجل ومطابقة الأرصدة حسب `../Supabase-Setup/docs/MIGRATION_AND_RECOVERY.md`، ثم تحميل نسخة الخادم في Flutter.
- التطبيق الجديد يُسجل deviceId جديدًا؛ يجب السماح به في الإدارة إذا وصل الحساب إلى حد الأجهزة. لا تُزل التطبيق القديم قبل مطابقة البيانات.
- قفل PIN واجهة حماية محلية؛ قاعدة SQLite تعتمد على حماية مساحة التطبيق في النظام، وليست قاعدة SQLCipher.
- النسخ الاحتياطية والاستعادة الإدارية تبقى مسؤولية الخادم. تغير epoch يوقف العمليات المعنية للمراجعة ويحفظ إدخال المستخدم.

## تشغيل وبناء Android

المتطلبات: Flutter 3.47.2/Dart 3.13.2، Android SDK، Java الخاصة بـ Android Studio. افتح هذا المجلد كمشروع **Flutter** في Android Studio مع إضافتي Flutter وDart.

```
flutter pub get
flutter run --flavor demo --dart-define=SADAD_DEMO=true
flutter build apk --debug --flavor demo --dart-define=SADAD_DEMO=true
flutter build apk --debug --flavor official
```

دخول متجر التجربة: **123 / 123** (و12345 / 12345 مدعوم). حساب العميل التجريبي: **0599999999 / 123123**؛ يعرض فقط الحركات الفعلية المسجلة بهذا الرقم في متجر التجربة. يبدأ الدفتر فارغًا.

لخادم مختلف، أعد البناء بـ `--dart-define=SADAD_API_URL=https://.../api` و`--dart-define=SADAD_API_KEY=...`. يتطلب HTTPS. تغيير العنوان يفصل البيانات المحلية عن البيئة السابقة.

APK debug للتثبيت والمراجعة الداخلية. الإصدار المنشور يحتاج keystore رسمي وإعداد `signingConfigs` في Gradle؛ release غير مضبوط للتوقيع في هذا المشروع. لا تُستخدم نسخة debug للنشر في المتجر.

## iOS

مشروع Runner والأيقونات وFace ID والميكروفون والتعرف على الكلام وKeychain وخلفية fetch مجهزة. الحد الأدنى في المشروع iOS **15** حسب قالب Flutter الحالي. بناء iOS وتوقيعه يحتاجان **Mac وXcode**؛ لم يُبنَ أو يُختبر هنا على Windows.

على Mac:

```
flutter pub get
flutter run --dart-define=SADAD_DEMO=true
flutter build ios --no-codesign
open ios/Runner.xcworkspace
```

اضبط Team والتوقيع والهوية النهائية في Xcode، وتحقق من البصمة والإملاء والطباعة والخلفية على iPhone. توقيت مزامنة الخلفية تحدده أنظمة التشغيل، والمزامنة الأمامية تعمل عند فتح التطبيق واستئنافه وكل 30 ثانية أثناء تشغيله.

## تنظيم المصدر

- `lib/core`: نماذج المبالغ والعمليات، API، الحسابات، SQLite، المزامنة، القفل.
- `lib/ui`: تسجيل الدخول، الواجهات الأصلية، النماذج، دفتر المتجر، التقارير والإعدادات.
- `lib/services/reports.dart`: تقارير PDF محلية.
- `assets`: الشعارات والأيقونة الأصلية وخط Tajawal بترخيص OFL.
- `android` و`ios`: ملفات تشغيل المنصة والصلاحيات.

توجد اختبارات للمبالغ، المعاينة، حفظ الطلبات في SQLite، إعادة الإرسال، التعارضات، تغير نسخة الخادم، عزل الحسابات، وقفل المزامنة، إضافة إلى اختبار الواجهات العربية على شاشة ضيقة. شغّلها باستخدام `flutter test`. حالة التحليل والبناء موثقة في ملف التسليم. التحقق مع خادم v3 حي وعلى الأجهزة المستهدفة مطلوب قبل النقل إلى الاستخدام الرسمي.
