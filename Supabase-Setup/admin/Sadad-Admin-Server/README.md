# خادم سدد ولوحة الأدمن

يقدّم هذا المجلد واجهة الإدارة وREST API للتطبيق من الخادم نفسه. بيانات كل متجر مرتبطة بمعرّف مستقل في SQLite، وكلمات المرور لا تُخزّن كنص صريح.

## تشغيل محلي للتجربة

1. ثبّت Node.js 24 أو أحدث.
2. انسخ `.env.example` إلى `.env` في هذا المجلد.
3. عيّن `INITIAL_ADMIN_KEY` إلى قيمة عشوائية طويلة. اترك اسم المستخدم وكلمة مرور الأدمن فارغين كي تنشئ الحساب من شاشة تأسيس لوحة الإدارة. كلمة مرور الأدمن يجب أن تكون 12 محرفًا على الأقل.
4. شغّل `node server.js` من هذا المجلد. المنفذ الافتراضي في `.env.example` هو `8081`.
5. افتح `http://localhost:8081/`، وأدخل مفتاح التأسيس الذي وضعته في `.env`، ثم أنشئ حساب الأدمن.
6. من لوحة الإدارة أنشئ حساب متجر واسم المستخدم وكلمة المرور المؤقتة. بعد ذلك سجّل دخول التطبيق الرسمي بحساب المتجر.

نسخة Android الرسمية التجريبية في هذه الحزمة تتصل بعنوان المحاكي `http://10.0.2.2:8081/api`. العنوان يعمل في محاكي Android على الكمبيوتر نفسه. لا يعمل على هاتف حقيقي؛ يلزم عنوان خادم يمكن للهاتف الوصول إليه.

## الاستضافة العامة عبر Docker وHTTPS

1. جهّز خادمًا ونطاقًا يوجّه إليه، وافتح 80 و443.
2. انسخ `.env.example` إلى `.env` وعيّن `DOMAIN` وبيانات أدمن قوية ومفاتيح سرية ثابتة.
3. شغّل `docker compose up -d --build`.
4. افتح `https://DOMAIN/` للوحة الإدارة. عنوان API هو `https://DOMAIN/api`.
5. ابنِ النسخة الرسمية بعنوان الخدمة العام: `-PSADAD_API_BASE_URL=https://DOMAIN/api`، ثم وقّعها بمفتاح إصدار خاص قبل التوزيع.

لا تتضمن الحزمة خادمًا عامًا منشورًا ولا إعداد Cloudflare Worker؛ يجب نشر هذا الخادم على بيئتك قبل ربط هواتف خارج الشبكة المحلية.

## الاشتراكات والأجهزة

- عند إنشاء متجر اختر اشتراكًا دائمًا أو مدة أيام أو حسابًا موقوفًا. خيار الإيقاف المؤقت يحفظ المدة المتبقية ويوقف عدّادها.
- الخادم يفحص تاريخ الانتهاء عند كل طلب ويجري فحصًا دوريًا كل دقيقة. عند انتهاء الاشتراك يوقف الحساب ويلغي جلساته؛ لا يعيد فتحه إلا الأدمن بتفعيل دائم أو تمديد جديد.
- لكل حساب جهاز واحد افتراضيًا. التطبيق ينشئ معرّف تثبيت دائمًا؛ تسجيل الخروج لا يحذف ربط الجهاز. تُمنع النسخ المنقولة عبر Android Backup.
- يضبط الأدمن الحد حتى 50 جهازًا، ويخفض الحد بإلغاء ربط الأجهزة الأقدم استخدامًا، كما يمكنه إلغاء أو إعادة السماح لجهاز بعينه أو إلغاء كل الأجهزة.
- إذا كان المتجر يسمح بأكثر من جهاز، يثبت كل مستخدم اسمه عند أول دخول من جهازه. لا يستطيع تغيير الاسم من التطبيق؛ يزيل الأدمن ربط الجهاز ليعيد تسجيله باسم جديد.
- لكل جهاز صلاحيات منفصلة لتسجيل الدفعات وحذف السجلات وحذف الأشخاص. يتحقق الخادم من تغييرات السجل: يمنع تعديل دين أو دفعة موجودة مباشرة، ويرفض حذف دين عليه متبقٍ، ويحسب سقف المدينين من المبالغ والدفعات الفعلية المخزنة لديه.
- يحتفظ الخادم بسجل نشاط يحدد اسم المستخدم والجهاز والعملية، ويظهر للأدمن ولصاحب المتجر.
- إعادة تعيين كلمة مرور التاجر تنهي كل الجلسات وتطلب تغيير كلمة المرور المؤقتة عند الدخول التالي.

## السجلات والاستعادة

- يحفظ التطبيق نسخة SQLite محلية ويزامن سجل المتجر إلى API بعد التعديل.
- قبل كل مزامنة يحفظ الخادم نسخة من بيانات المتجر. يحتفظ بآخر 100 نسخة لكل متجر.
- تحفظ أسماء منفذي إضافة الأشخاص والديون والدفعات ضمن السجل، ويحتفظ سجل النشاط بعمليات الحذف واسم منفذها.
- عند حذف التاجر زبونًا، يحفظ الخادم أرشيفًا دائمًا مستقلًا لذلك الزبون مع ديونه ودفعاته، ويظهر في قسم «أرشيف الزبائن المحذوفين» داخل تفاصيل المتجر.
- يستطيع الأدمن استعادة سجل الزبون المؤرشف إلى حساب المتجر. يبقى الأرشيف محفوظًا بعد الاستعادة للرجوع إليه.
- من تفاصيل المتجر في لوحة الأدمن اختر نسخة واستعد المتجر كاملًا أو شخصًا واحدًا فقط. قبل الاستعادة تُحفظ نسخة أخرى للحالة الحالية.
- الاستعادة ترفع رقم إصدار السجل، فيتعرف التطبيق على نسخة الخادم عند المزامنة التالية بدل الكتابة فوقها بصمت.
- النسخ داخل قاعدة SQLite نفسها؛ خذ نسخًا احتياطية دورية من volume `sadad-data` إلى مكان آخر لحماية البيانات من فقدان القرص.

## التخزين والتشغيل

- تستخدم الحزمة SQLite على خادم واحد في volume دائم. لا تشغّل عدة نسخ API تكتب إلى ملفات SQLite منفصلة؛ هذه البنية ليست إعدادًا متعدد الخوادم.
- مجلد `DATA_DIR` في Docker مضبوط على `/app/data`، والـ volume `sadad-data` يحفظ `sadad.sqlite` ونسخ الاستعادة.
- الخادم Node.js 24 أو أحدث. للتطوير المحلي: انسخ `.env.example` إلى `.env`، ثم شغّل `node server.js`. API الافتراضي للتطبيق هو `http://10.0.2.2:8081/api` للمحاكي فقط.
- أدخل رابط API في شاشة الدخول، وينتهي بـ `/api`. جهاز Android الحقيقي وإصدار Release يحتاجان عنوان HTTPS عامًا؛ الاتصالات غير المشفرة مسموحة في Debug فقط.
- يرفض الخادم كلمات مرور الأدمن الأقصر من 12 أو الأطول من 128 خانة، ويحدّ محاولات الدخول على مستوى عنوان الشبكة والحساب في قاعدة البيانات. لا تفعّل `TRUST_PROXY_HEADERS` إلا إذا كان الخادم خلف وكيل موثوق يكتب عنوان IP الحقيقي بنفسه. إعداد Cloudflare Worker يمرر عنوان Cloudflare الموثوق.
- صورة Docker تعمل كمستخدم `node` غير مميز. إذا كان لديك volume قديم منشأ كمستخدم root، تأكد من صلاحية الكتابة لمجلد البيانات قبل الترقية.
- لا ترفع `server/data/sadad.sqlite` أو ملفات `.env` إلى مستودع أو موقع عام. خزّن نسخ قاعدة البيانات الاحتياطية على تخزين مشفر ومقيد الصلاحيات، واحتفظ بنسخة من `TOKEN_ENCRYPTION_KEY` خارج الخادم.
- قفل التطبيق المحلي لا يشفر قاعدة SQLite. Android يحمي ملفات التطبيق ضمن مساحة التطبيق ويمنع النسخ الاحتياطي هنا، لكن الأجهزة المروّتة أو المفتوحة قد تكشف البيانات؛ استخدم تشفير الجهاز ولا تخزن بيانات حقيقية على جهاز مخترق.
- هذا الخادم ما زال نسخة SQLite القديمة. توجد نسخة الترحيل إلى Postgres وEdge Function في `../../supabase/`؛ قاعدة Supabase أُنشئت والخدمة `sadad-api` منشورة، لكن لم تُستورد بيانات SQLite بعد. لا تحوّل المستخدمين الحاليين قبل استيراد ملف قاعدة بيانات الخادم الفعلي.

## دخول الأدمن

على قاعدة جديدة ينشئ الخادم حساب الأدمن من متغيري `INITIAL_ADMIN_USERNAME` و`INITIAL_ADMIN_PASSWORD`، ويطلب تغيير كلمة المرور عند أول دخول. لا يعيد الخادم تعيين الحساب عند إعادة التشغيل إذا كان أدمن موجودًا.

## WhatsApp

يحتاج الإرسال الحقيقي إلى حساب Meta WhatsApp Business Platform، ورقم مرسل مسجل، و`META_GRAPH_VERSION`. يفعّل الأدمن الميزة لكل متجر، ثم يربط صاحب المتجر رقم Phone Number ID ورمز Meta من داخل التطبيق. تحفظ رموز Meta مشفرة بمفتاح `TOKEN_ENCRYPTION_KEY` ولا تعاد إلى التطبيق.
